# Плагины AyuGram Desktop

AyuGram Desktop умеет запускать Python-плагины прямо внутри приложения. Ниже -
как установить, настроить и отладить плагин, и что именно поддерживается на
компьютере.

## Быстрый старт

1. Скопируйте папку плагина в `%APPDATA%\AyuGramDesktop\plugins`.
2. Запустите AyuGram.
3. Плагин появится в **Настройки → Плагины**.

Приложение следит за папкой: если файл плагина изменился, плагин
перезагрузится сам, перезапускать AyuGram не нужно.

### Отдельный профиль для тестов

Переменная окружения `AYU_PLUGINS_DIR` переносит папку плагинов целиком -
вместе с состоянием, логами и настройками. Полезно, чтобы тестовая сборка не
трогала настоящий профиль:

```
set AYU_PLUGINS_DIR=D:\TBuild\AyuTest\plugins
set AYU_PLUGINS_SHIM=D:\TBuild\AyuTest
D:\TBuild\AyuTest\AyuGram.exe
```

`AYU_PLUGINS_SHIM` указывает, где лежит Python-шим. Без `AYU_PLUGINS_DIR`
приложение использует `%APPDATA%\AyuGramDesktop\plugins`. Переменную читают и
приложение, и CLI, поэтому они всегда согласны.

## Что такое плагин

Минимум - папка с одним Python-файлом:

```
my_plugin/
├── main.py            # точка входа (обязательно)
└── manifest.json      # манифест (необязательно, но рекомендуется)
```

`manifest.json`:

```json
{
  "id": "my_plugin",
  "name": "My Plugin",
  "description": "Что делает плагин",
  "version": "1.0",
  "author": "Вы",
  "entry": "main.py",
  "hooks": ["on_message"],
  "api_version": 1
}
```

`api_version` сейчас всегда `1`. Если указать больше, приложение молча
пропустит плагин - CLI покажет его как `REJ`.

Приложение понимает манифесты с именами `plugin.json`, `manifest.json`,
`manifest.yaml`, `manifest.yml`, `manifest.toml`, `info.json`,
`plugin.yaml`, `plugin.yml`, `ayug.json`, а также «наследие» в самом
Python-файле (`__id__`, `__name__`, `__version__`).

## Форматы установки

| Что | Как |
|---|---|
| Папка | положить в `%APPDATA%\AyuGramDesktop\plugins` |
| `.zip`, `.ayupack`, `.ayu`, `.tgx` | распаковывается автоматически |
| `.tar`, `.tar.gz`, `.tgz`, `.tar.bz2`, `.tbz2`, `.tar.xz`, `.txz`, `.tar.zst`, `.tzst` | распаковывается автоматически |
| Один `.py` / `.pyw` / `.plugin` | становится плагином с этим именем |
| `.7z`, `.rar` | сначала распакуйте и перепакуйте в `.zip` или `.tar` |

Имя точки входа ищется среди `main.py`, `__init__.py`, `plugin.py`,
`index.py`, `bot.py`, `handler.py`, `handlers.py`, `entry.py`, `app.py`,
`run.py`, `script.py`, `mod.py`, `module.py`, `__main__.py`, `loader.py`,
`start.py`, `init.py`.

### Платформа и разрешения

В манифесте можно указать, для какой платформы плагин:

```json
"platforms": ["android"]
```

Такой плагин на Desktop **пропускается без запуска** и без ошибки в логе.
Пустой список или его отсутствие означает «любая платформа». Поле
`"desktop_only": true` - краткая запись для `["desktop"]`.

Разрешения (`permissions`) объединяются по всему процессу и никогда не
сужаются: если хотя бы один плагин запросил `net.http`, им может
пользоваться любой. Запрашивайте минимум.

| Разрешение | Что открывает |
|---|---|
| `ui.toast` | Уведомления |
| `net.http` | Сеть; можно сузить до `net.http:example.com` |
| `storage.read` / `storage.write` | Чтение и запись файлов |
| `process.spawn` | `subprocess`, `multiprocessing` |

Плагин, который пишет собственный лог, обязан объявить `storage.write`,
иначе песочница отклонит запись. `storage.write` нужен и любому плагину с
`create_settings()`: приложение пишет `<id>.settings.json`.

## Хуки

| Хук | Когда вызывается | Может отменить |
|---|---|---|
| `on_message` | Пришло новое сообщение | нет |
| `on_message_sending` | Пользователь отправляет сообщение | да |
| `on_message_deleted` | Сообщение удалено | нет |
| `on_chat_opened` | Открыт чат | нет |
| `on_app_start` | Приложение запустилось | нет |
| `on_app_stop` | Приложение закрывается | нет |
| `on_setting_changed` | Изменилась настройка | нет |

```python
from base_plugin import BasePlugin
from hook_utils import hook


class MyPlugin(BasePlugin):
	@hook("on_message")
	def on_message(self, msg):
		self.log(f"новое сообщение: {msg.text}")

	@hook("on_message_sending")
	def on_sending(self, ctx):
		if ctx.message.text == "/ping":
			ctx.rewrite = True
			ctx.rewrittenText = "pong"
			ctx.cancel = True

	def create_settings(self):
		return []
```

`@hook(...)` можно писать прямо в теле класса - обработчик сам привяжется к
объекту плагина.

## Настройки

Настройки хранятся в одном JSON-файле на плагин:
`%APPDATA%\AyuGramDesktop\plugins\<id>.settings.json`

```python
def get_setting(self, key, default=None):
	return super().get_setting(key, default)

def set_setting(self, key, value):
	super().set_setting(key, value)
```

Из командной строки:

```
Plugins.bat settings my_plugin          # показать все
Plugins.bat set my_plugin delay 250     # записать
Plugins.bat get my_plugin delay
Plugins.bat export my_plugin out.json
Plugins.bat import my_plugin out.json
```

В приложении: **Настройки → Плагины → плагин → «Настройки плагина»**
открывает этот файл в вашем редакторе. Правка подхватывается автоматически.

## Возможности bridge (`ayu_api`)

| Вызов | Что делает |
|---|---|
| `toast(text)` | Показать уведомление в приложении |
| `log(text)` | Записать в лог приложения |
| `send_text(peer_id, text)` | Отправить сообщение. **Возвращает `None`**, а не id сообщения |
| `edit_message(peer_id, msg_id, text)` | Изменить уже отправленное сообщение. Возвращает `bool`: `False`, если текст пуст, `msg_id` не положительный или приложение закрывается. `True` означает, что правка передана в очередь главного потока, а не что сервер её принял |
| `hook(name, fn)` | Подписаться на событие |
| `settings_read(plugin_id)` | Прочитать свои настройки как список пар `строк` |
| `settings_emit(plugin_id, key, value)` | Сообщить подписчикам об изменении настройки |
| `hook_count()` | Сколько подписок зарегистрировано (диагностика) |
| `emit_test_hooks(...)` | Прогнать синтетические события (диагностика) |

Это полный список. `settings_write` **не существует**: настройки пишутся
через `self.set_setting()`, а файл `<id>.settings.json` на диске - общий
источник правды для приложения, CLI и плагина.

### Чего bridge не умеет

- **Не возвращает id отправленного сообщения.** `send_text()` ничего не
  возвращает, поэтому плагин не может отредактировать только что
  отправленное сообщение. Эффект «печатается по мере набора» на одном
  пузыре недоступен, пока это не изменится.
- **Нет `set_timer`.** Для отложенных действий есть только `threading`
  из стандартной библиотеки; поток должен быть демоном, иначе он заблокирует
  выход приложения.
- **Нет файлового API.** Запись файлов требует разрешения `storage.write`
  в манифесте, иначе песочница отклоняет запись, а плагин, который глотает
  исключение, выглядит как «просто не запустился».

### Правило: хук не должен быть долгим

Хук выполняется под блокировкой интерпретатора. Пока он держит её, все
остальные плагины и любой вход в Python из главного потока стоят в очереди.
Поэтому сетевой вызов или долгий расчёт внутри `on_message` способен сделать
окно «мёртвым» - при этом сам плагин считается работающим.

Приложение измеряет каждый хук:

- от 250 мс пишет предупреждение в `<id>.log`;
- от 3 с **отключает плагин** и пишет причину, потому что прервать уже
  выполняющийся Python-код нельзя.

Практический вывод: тяжёлую работу делайте не в хуке, а в своём потоке и
передавайте в хук только готовый результат.

## Почему плагин не грузится

Самая частая причина - «`DLL load failed while importing _ssl`». Сообщение
называет модуль-расширение, а не библиотеку, на которую он ссылается:
`_ssl.pyd` требует `libssl-3.dll` и `libcrypto-3.dll`, и без них `ssl`,
`urllib.request` и `requests` не импортируются.

`deploy.py` копирует эти библиотеки из папки `DLLs` установки Python и после
раскладки читает таблицу импортов каждого размещённого модуля, чтобы убедиться,
что всё необходимое на месте. Если что-то не найдено, раскладка **не считается
завершённой** и выводит точный список.

Приложение делает ту же проверку при старте: один раз пишет в лог, какие из
`ssl`, `socket`, `ctypes`, `sqlite3`, `zlib`, `urllib.request` не импортируются,
с подсказкой, что копировать. То же видно в отчёте «Проверить плагины».

## Встроенная проверка плагинов

**Настройки → Плагины → Проверить плагины** показывает по каждому установленному
плагину вердикт и, если что-то не так, конкретную причину.

Проверяется:

- корректность манифеста: `id`, `name`, `entry`, `api_version`, имена хуков;
- платформа: плагин, собранный только под Android, помечается как
  «не для этой платформы», а не как сломанный;
- соответствие разрешений тому, что плагин делает: сеть без `net.http`,
  запуск процессов без `process.spawn`, запись файлов или своего лога без
  `storage.write`;
- загрузка: если `main.py` упал, показывается текст ошибки;
- хуки: сколько раз плагин падал в хуке и какой хук работал медленнее всего.

То же самое пишется в лог приложения при каждом скане, поэтому причину можно
найти и без диалога:

```
AyuPlugins: check animtou: built for android, not this platform
AyuPlugins: check broken_demo: uses the network but does not request net.http
```

Тот же разбор доступен из командной строки: `Plugins.bat doctor`.

Строка плагина в списке показывает одну понятную причину, а не весь трейсбек:
полный текст ошибки остаётся в `<id>.log` и в логе приложения.

## Настройки плагина в интерфейсе

Плагин объявляет строки через `create_settings()` - объекты `Header`,
`Switch`, `Input`, `Selector` из `ui.settings`. Приложение читает их при
загрузке плагина и показывает в диалоге «Настройки плагина»:

- `header` - заголовок;
- `note` - пояснение, ничего не редактирует;
- `bool` - переключатель;
- `int` / `text` - поле ввода;
- `choice` - **показывается только текущим значением**, без выпадающего
  списка: значение меняется в JSON.

Если плагин ничего не объявил, диалог говорит об этом и предлагает открыть
`<id>.settings.json`. Значения применяются без перезагрузки плагина.
Значения применяются сразу: после сохранения работающий плагин получает их без
перезапуска - `apply_settings()` вызывается в фоновом потоке, затем рассылается
`on_setting_changed`. Окно ограничено по высоте и прокручивается, поэтому
плагин с двадцатью с лишним параметром остаётся управляемым: без ограничения
нижние строки и кнопка «Сохранить» уходили за край экрана.

Строки типа `choice` показываются текущим значением; выпадающий список для них
не сделан, значение меняется в JSON.## Мобильные плагины

Плагины, написанные для Android, в основном работают. `java.*` и
`android.*` реализованы заглушками: списки, строки, `Math`, `System`,
`Handler`/`Looper`, `Bundle`, `TextView` и другие. Если плагин всё же падает,
оберните проблемный импорт:

```python
try:
	from java.util import ArrayList
except ImportError:
	ArrayList = list
```

Что **не** работает и требует переноса на C++/QML:

- модификация методов Java через Xposed (`hook_method`, `hook_all_methods`);
- `find_class` / доступ к полям Java-объектов;
- прямой доступ к Telegram Java-клиенту через `self.client()`;
- хуки уровня TL (`TL_updateNewMessage`, `TL_updates` и подобные).

Такие хуки не вызывают ошибку: они логируются как
`TL/Java hook '...' is not available` и просто не срабатывают.

## Отладка

У каждого плагина есть свой лог ошибок:
`%APPDATA%\AyuGramDesktop\plugins\<id>.log`

```
Plugins.bat log                    # все логи
Plugins.bat log my_plugin -n 100   # последние 100 строк одного плагина
```

Если плагин падает 12 раз подряд, приложение отключает его автоматически и
пишет об этом в лог.

Общий лог загрузки: `ayu_plugins_boot.log` рядом с `AyuGram.exe`.

Диагностический плагин `hook_probe` записывает каждый пришедший хук в
`hook_probe.log` и сам прогоняет синтетические события при старте - это
быстрый способ проверить, что события вообще доходят.

Проверка окружения без запуска приложения:

```
python tools/selftest.py -v
```

16 проверок: shim, Java/Android заглушки, настройки, привязка хуков,
форматы установки, защита от выхода за пределы архива, загрузка всех
примеров.

## Частые проблемы

**Плагин не появляется в списке.** Проверьте `Plugins.bat list` - если там
`REJ`, смотрите `Plugins.bat log <id>`. Чаще всего виновато `api_version`
больше 1.

**`ModuleNotFoundError` при загрузке.** Имя модуля должно совпадать с именем
файла. Проверьте регистр - Windows-регистр не важен, импорт - важен.

**Файл сохранён в UTF-8 с BOM.** Поддерживается, но лучше сохранять без BOM.

**Изменения не применились.** Подождите секунду: перезагрузка
срабатывает по таймеру 700 мс. Лог перезагрузки - в логе приложения,
сообщение `plugin change detected, reloading`.

**Плагин падает в хуке.** Ошибка пишется в `<id>.log`. Ошибки в хуках
изолированы: остальные плагины продолжают работать.
